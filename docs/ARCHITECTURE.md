# Архитектура NURSERIK CHEMISTRY

## Решение: многостраничная статика + внешний бэкенд

**Фронтенд остаётся на чистом JS/HTML/CSS с собственной сборкой `build.mjs`.** React и TypeScript пока не вводятся. Причины:

- Существующий код (камера, графики, калькуляторы — около 3000 строк) написан на чистом JS. Он работает и покрыт браузерными тестами. Переписывание не даёт ученику ничего нового.
- Сельские школы с медленным интернетом: главная страница весит 46 КБ без единой JS-зависимости.
- GitHub Pages обслуживает реальные папки (`/kinetics/index.html`), поэтому нет проблемы с прямыми ссылками и обновлением страницы, которая есть у SPA-роутинга.
- К пересмотру стоит вернуться, когда появятся личные кабинеты с большим количеством состояния. Тогда разумно ввести TypeScript (через `tsc` без фреймворка) или лёгкий компонентный слой.

**Бэкенд (этап 4): Supabase.** Используются Auth, PostgreSQL, Row Level Security и Edge Functions. Клиент получает только `anon`-ключ: он публичен по своей природе, а весь доступ ограничивают политики RLS. Секреты (`service_role`, ключ LLM API) хранятся только в переменных окружения Edge Functions и никогда не попадают в репозиторий.

## Структура

```
build.mjs              сборка всех страниц; проверка переводов
src/site/              платформа: дизайн-система, шапка, подвал, страницы
  site.css             токены светлой/тёмной темы, режим доступности
  site.js              язык, тема, доступность, мобильное меню
  header.html, footer.html
  home.html            главная → /index.html
  research.html        «Об исследовании» → /research/index.html
  hero-gas.js          модель газа на главной (2D, e^(−Eₐ/kT))
src/kinetics/          курс «Химическая кинетика» (бывший сайт-урок)
tests/browser.mjs      браузерные тесты через Chrome DevTools Protocol
docs/                  аудит, архитектура
RESEARCH_METHODOLOGY.md
```

Собранные страницы (`index.html`, `research/`, `kinetics/`) коммитятся в репозиторий: GitHub Pages публикует ветку `main` как есть. Позже это можно перевести на GitHub Actions; для этого нужно поменять источник Pages в настройках репозитория.

### Переводы

- В исходниках текст пишется маркером `⟦қазақша‖русский‖english⟧`.
- Сборка заменяет маркер на `data-i="N"` и складывает переводы в массивы `I18N.ru` и `I18N.en` каждой страницы.
- Динамические строки задаются через `L(kk, ru, en)`.
- Сборка падает, если в русском тексте есть казахские буквы или в английском есть кириллица.
- Выбор языка хранится в `localStorage` под ключом `nc-lang` и общий для всех страниц.

### Тема и доступность

Атрибуты на `<html>`:

- `data-theme` — `light` или `dark`; если атрибута нет, тема берётся из системы;
- `data-large` — крупный шрифт;
- `data-contrast` — высокий контраст;
- `data-calm` — меньше анимации.

Атрибуты выставляются до первой отрисовки встроенным скриптом в `<head>`.

## Безопасность (обязательные правила для этапов 4–9)

- Роль пользователя хранится только в базе (`profiles.role`), меняется только администратором. Политики RLS проверяют роль через `auth.uid()`, а не через данные клиента.
- Ученик видит только свои записи. Учитель видит записи учеников своих групп (`class_memberships`).
- Итоговые оценки и эталоны контрольных заданий не попадают в клиент. Проверка выполняется в Edge Function.
- Исследовательские наборы содержат псевдонимизированный идентификатор. Таблица соответствия доступна только администратору исследования.
- Каждое изменение оценки учителем пишется в `audit_logs`.
